# 让她的一天跟着真实的课表走

> 一个高中生不是 24 小时在线的。她有早读、有晚自习、有午睡。
> 不知道这些的 agent，会在她上课的时候热情地连发五条。

---

## 一、三条时间线索

| 线索 | 来源 | 作用 |
|---|---|---|
| **今天是什么日子** | 每日生成的一次性日程（`build-day`） | 今天是周几、上什么课、有没有考试 |
| **现在处在哪一段** | 运行时按当前分钟算 | 上课 / 课间 / 午睡 / 晚自习 / 夜里 |
| **这个段能不能说话** | 守卫表 | 主动消息发不发、回复延迟多久 |

注意：**这三样必须每天现算，不能写死。**
写死"周一下午有数学课"的代码，会在调休那天让她在考试中途冒出来。

---

## 二、先决定"几点发"，再决定"说什么"

我们最早的顺序反了：

```
先算场景（现在在上课）→ 守卫拒绝 → 抖动 8 分钟 → 什么都不发
```

正确顺序：

```
抖动 0~8 分钟 → 到点重新算场景 → 守卫判断 → 生成 → 发
```

否则会出现：**决定的时候是下课，真正发出去的时候已经在教室里了。**
反过来的 bug 也一样真实：7:55 算出来的场景是"在上课"，说出来的话像翘课。

抖动放在最前面，场景按**抖动之后的时间**算。

---

## 三、守卫表

| 时段 | 类型 | 主动消息 | 回复延迟 |
|---|---|---|---|
| 上课 | `class` | 不发 | 正常（她偷偷看手机） |
| 午睡 | `nap` | 不发 | 慢 |
| 晚自习 | `study` | 20% 偷发一次 | 慢 |
| 深夜 | `sleep` | 只在熬夜/失眠时发 | 8~20 秒 |
| 其他 | `free` | 正常 | 3~8 秒 |

**"上课不发"不等于"不理人"。**
她上课时会回，只是回得短、回得慢。这两件事要分开配。

---

## 四、场景要有科目

只给"在上课"，她说不出"数学老师又拖堂"。
日程里带上科目，场景里带出来：

```js
function slotState(now, day) {
  const slot = day.subjects.find(s => now >= s.start && now < s.end);
  if (!slot) return { type: "free", label: "在家" };
  return { type: "class", label: `${slot.subject}课`, subject: slot.subject };
}
```

产出：`{"state":{"label":"语文课"},"scene":"[在上语文课，手机塞桌斗里…]"}`

## 五、两个我们踩过的坑

### 坑 1：课程表模板不等于她

通用模板给每个学生都排化学、物理。
**文科生没有化学课** —— 她一句话就把身份卖了。

课表要由**她的身份**约束：文科 → 语数英 + 政史地。
生成日程时把"她是谁"传进去，别用默认模板。

### 坑 2：切片把晚段吃掉了

按时间切片取"今天剩下的课"时，如果边界写错（`< end` 写成 `<= start` 之类），
**最后一两节课会静默消失**。失配的表现不是报错，是她下午三点说"我放学了"。

修法：生成日程后断言总课节数，和课表比对，不等就重算。

---

## 六、和主动消息配合

这一段配合 `proactive-delivery`（主动投递）：

```
每条主动消息 = 什么时候发（抖动） + 能不能发（守卫） + 说什么（场景 + 当天事件）
```

缺任何一项，都会出现"她半夜三点问你在干嘛"这种事故。
