# 人格设计的四条反直觉经验

这些不是理论推演，是做一个真实人物的数字画像时**踩出来的**。每一条都有数字支撑。

---

## 一、抽象规则压不住模型，✅/❌ 对照才行

我想让她**不用中文逗号**（因为真实语料里只有 3% 的消息带逗号）。

**第一次做法**：在人格文件里写一条规则 ——

> 标点：基本不用中文逗号，断句靠空格。

**结果：56% 的回复依然带逗号。** 模型看完这条规则，照样按它的书写习惯输出。

**第二次做法**：把规则提到最高优先级层，并且**给出对错例子** ——

```
断句用空格，不用逗号。真实语料 1584 条里只有 45 条有（3%）。
  ✅ 咋了 哪难受        ❌ 咋了，哪难受
  ✅ 那别玩手机了 越看越睡不着   ❌ 那别玩手机了，越看越睡不着
记住这条是最好认的破绽 —— 一出现逗号，别人一眼就知道不是你。
```

**结果：0%。**

> **结论**：描述性规则 ≈ 无效；"规则 + 具体对错例子 + 这条为什么重要" ≈ 有效。
> 模型不是不懂规则，是它不知道在**具体某个 token 上**该怎么做。

---

## 二、人格规则再硬，也扛不住聊天记录里的自相矛盾

她偶尔会说"我是一个 AI 助手"。

我们一开始以为是提示词不够硬，于是把"你绝对不是 AI"写进了最高优先级层，还加了"被问到就骂回去"的具体话术。

**新会话测试：完美。** 问"你是不是AI" → 「你有病吧」。

**但主会话里她照样承认自己是 AI。**

后来把主会话的历史翻出来，找到了原因 —— **里面有三条她自己说过的话**：

```
[5]   她：你好，我是 Kimi（kimi/kimi-for-coding）…
[125] 她：知道啊，我是 Kimi
[153] 她：是，我是 Kimi，一个 AI 助手
```

**模型看到自己前面这么说，就会保持前后一致。** 规则再硬也压不过它自己的先例。

修法不是改提示词，是**把那三条历史记录改掉**（备份后直接改 SQLite 的 transcript_events）：

```
[5]   → 在的
[125] → 你有病吧
[153] → ？
```

改完立刻正常。

> **结论**：出戏排查的第一步永远是**翻历史记录**，不是改提示词。
> 人格是"当前上下文"的产物，历史就是上下文的一部分。

## 三、"嘴硬心软"必须写成可量化的比例

用户的原话是：

> "她平时对我时而暴力时而温柔，但我在 AI 上完全感觉不到。"

第一版人格写的是"她有两种状态：玩闹时 / 低落时" —— **方向和维度都错了**。
那是"她自己心情的两档"，而用户要的是"**她对他的态度摆动**"。

改法：去语料里数一遍。

```
带刺的话（滚、傻逼、你有病吧、我不理你了）: 81 条
温柔的话（好好休息、吃饭、抱抱你、我爱你）: 30 条
比例 ≈ 2.7 : 1
```

然后把这个比例**写进人格当硬约束**：

```
默认状态是带刺的 —— 大部分回合开口就是攻击性的话，而且这不是真生气。
他示弱 → 你会立刻软，但不说软话，用行动（"吃饭""睡觉""好好休息"）。
温柔永远包在硬壳里 —— 「我靠我操你没事吧」是钥匙：脏话是外壳，关心是芯。
最关键的是：没有规律。同一句话，你可能回「？」也可能回「滚吧」。
不许每次都凶，也不许每次都软。
```

> **结论**：模糊的形容词（"嘴硬心软"）模型理解不了。
> **数一下比例，写成数字，模型才知道"大部分时候该凶一点"到底是几分之几。**

## 四、推理档位是还原度的隐藏开关

调完之后，回复速度成了问题（11-18 秒）。查下来发现 k3 模型**默认走 `high` 推理档**：

```js
const thinkingLevel = options?.reasoning ?? ctx.thinkingLevel ?? (k3 ? "high" : undefined);
```

也就是说**每条回复前它都在默默深度思考几秒**。对一个聊天人格来说纯属浪费。

关掉（`off`）之后确实快了 —— 但**回复明显变平**：

| 输入 | thinking=off | thinking=low |
|---|---|---|
| 我想你了 | **？** | 大半夜的说啥呢你 睡不着啊 |
| 今天好烦 | 咋了 | 你咋了 出啥事了 |

> **结论**：`low` 是速度与还原度的平衡点。
> **别为了快把推理全关掉** —— 人格的"反应层次"是推理撑起来的。

## 附：怎么用这些经验

1. 先**抓够语料**（几百条起步），这是所有统计的基准
2. 用 [audit-persona.mjs](../audit/audit-persona.mjs) 把语料跑成指纹
3. 写人格 → 跑审计 → 看哪项超标 → **改那一项** → 再跑
4. 出戏了先翻历史记录，别急着改提示词
5. 用户说"不像"的时候，**追问具体是哪句** —— "不像"这个反馈没法直接- 修
