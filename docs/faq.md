# FAQ

## 关于范围

### 为什么仓库里没有抓取工具？

因为它是唯一一个**开源之后会伤害到别人**的部件。

从自己手机上导出自己的聊天记录，本身没问题。但同一个工具指向别人的手机，就是另一回事 —— 而工具本身没法区分这两种用途。

我们选择不开源它。这个决定不接受讨论。

### 能用这个仓库做公众人物 / 明星的人格吗？

技术上可以，**但请想清楚三件事**：

1. 对方的公开形象和你生成的形象，边界在哪
2. 公开传播时会标注"这是 AI"吗
3. 如果对方本人看到了，你站得住吗

仓库里所有工具都不限制你的用途。但**工具中立不等于行为中立**。

### 生成的内容能商用吗？

代码是 MIT，随便用。**但你的人格内容、语料、生成形象属于各自的版权/肖像权范畴**，那是你和相关人士之间的事，不是这个仓库能授权的。

## 关于"不像"

### 用户说"不像她"，但我不知道从哪改

**别问"哪里不像"，问"她哪句话绝不会说"。**

"不像"这个反馈没法直接修。能修的是具体的：哪一句、哪个词、哪种语气。让对方指一条给你看，改一条，再跑一次审计。

### 为什么我写了"不要用逗号"，模型还是用？

因为**描述性规则对模型几乎无效**。

"不要用逗号"是一个抽象指令，模型不知道该在哪个 token 上执行。必须给对照例子：

```
✅ 咋了 哪难受        ❌ 咋了，哪难受
```

并且放在**最高优先级层**。我们把这条从"氛围描述"改成"规则 + 例子 + 为什么重要"之后，逗号率从 56% 直接归零。

### 角色老是说"我是一个 AI"，提示词写多硬都没用

**先翻历史记录，不要先改提示词。**

模型会跟自己的先例保持一致。如果 transcript 里它以前说过"我是 AI 助手"，规则再硬也压不住。

查法：把会话的 transcript 导出来，搜 `AI`、`助手`、`模型`。找到那几条，改掉。

### 语料多少条够用？

**几百条起步，一两千条比较稳。**

低于 200 条时，统计出来的"指纹"波动很大（比如逗号率可能因为几条长句就偏了）。我们用约 1500 条覆盖近一年的聊天，各项指标的稳定性才够。

另外：**语料要覆盖不同场景**（日常、情绪、争执）。如果全是甜言蜜语，做出来的角色只会甜。

## 关于审计工具

### 必须装 OpenClaw 吗？

**不必须。** 只算语料基准（`--corpus`）是纯 Node，零依赖。

只有跑完整审计（`--battery`）时需要 OpenClaw，因为要通过它调模型。

### 指标阈值是固定的吗？

不是。`audit-persona.mjs` 里的 `tol` 是**经验值**，你应该按自己的语料调整：

```js
const METRICS = [
  { id: "comma", label: "含中文逗号", test: s => s.includes("，"), tol: 12 },
  //                                                            ↑ 改这里
];
```

原则：**语料里本来就低的指标，容差要小**（比如 0% 的指标，容差 5% 都算多）；本来就高的，容差可以大一点。

### 可以加自己的指标吗？

可以，往 `METRICS` 数组里加一条：

```js
{ id: "laugh", label: "出现'笑死'", test: s => s.includes("笑死"), tol: 15 },
```

要不要加，看它是不是**能区分"像"和"不像"**。加一堆没区分度的指标只会让输出变吵。

## 关于平台接入

### 微信能发语音吗？

**协议支持，插件没实现。**

iLink 的 `MessageItemType` 里有 `VOICE = 4`，但插件的 `send-media` 只路由 `video/*` 和 `image/*`，其它类型一律当**文件**发出去。

想发真语音条（不是文件），需要：TTS 生成音频 → SILK 编码 → 用 VOICE 类型上传 → **给插件打补丁**。插件在 node_modules 里，更新会被覆盖。

### 定时让她主动发消息，为什么老是不成功？

见 [proactive-delivery.md](proactive-delivery.md)，两个死胡同都记了。最快的判断方法：

```bash
# 日志里有没有这一行
grep "outbound: text sent OK" <日志>
```

没有 → 根本没投递；有 `contextToken missing` → 目标格式带了 `user:` 前缀，键对不上。

### 网关重启后她突然不说话 / 报错了

先看启动日志。最常见的一个：

```
hooks.allowedSessionKeyPrefixes must include 'hook:' when hooks.defaultSessionKey is unset
```

配置里加了 `allowedSessionKeyPrefixes` 但漏了 `hook:`，网关直接起不来。

## 关于模型

### 为什么要用低推理档位？

人格的"反应层次"是推理撑起来的 —— 全关掉（`off`）之后回复会明显变平：

| 输入 | off | low |
|---|---|---|
| 我想你了 | ？ | 大半夜的说啥呢你 睡不着啊 |

但 `high` 会让每条回复多花好几秒。**`low` 是平衡点。**

### 换个模型会不会更像我？

不一定。**模型换了对"像"的影响，远小于规则写法的好坏**。

我们试过三个档位：一个小的会**照抄语料里的原话**（作为台词库用，很出戏），换回大的才正常。

先用审计工具量，再决定要不要换。
